# 一句话定位

**把每一次带看，变成一份专业的客户报告。**

给买方经纪（Buyer's Agent）用的 AI 带看工具：一键录音，AI 自动生成结构化、专业、给客户看的带看报告。

不是市场，不是内容平台，不是数据网络。是一个每天用、能立刻省时间的私有工作工具。

------------------------------------------------------------------------

# 问题

买方经纪每次带看都在做重复的、耗时的手工工作：

- 边看边用手机拍照、录像、发微信语音
- 看完之后凭记忆整理笔记
- 手动写总结发给客户
- 客户看多套房之后，经纪需要手动对比、提炼

这些工作：

- 占用经纪大量非计费时间
- 依赖记忆，容易遗漏细节
- 输出质量不稳定，取决于经纪当天有没有空整理
- 没有留下可复用的记录（下次同一套房子再有客户看，一切从零开始）

# Why Now

核心驱动力是技术，市场进入时机由地域因素加成，两者分开看：

## 技术驱动力（长期、不因地域变化）

1. **AI 技术成熟**：语音转写、房间识别、内容结构化，现在可以在几分钟内完成，成本可控——这是产品能够存在的根本前提。
2. **买方经纪的信义义务（fiduciary duty）**：法律上买方经纪对买家负责，这跟挂牌经纪对卖家负责的立场不同——买方经纪本就有更强的结构性动机产出客观内容，不需要额外说服，这是一个跨地区通用的结构性事实。

## 市场进入时机（BC / 当前阶段的加成因素，不是价值主张的根基）

3. **BC 佣金监管变化（2026 BCFSA 改革）**：买方经纪的佣金现在需要通过书面买方代理协议单独协商，不再默认由挂牌佣金池分配。这让买方经纪比以往更需要**向客户证明自己的专业价值**，是一个很好的切入时机，但属于地域性、时效性因素——产品的核心价值主张不应该建立在某一地区的监管细节上，未来扩展到其他地区时，这条不必然成立。

# 目标用户：为什么是买方经纪，不是笼统的"Realtor"

刻意收窄，不是笼统面向所有经纪人：

| | 挂牌经纪（Listing Agent） | 买方经纪（Buyer's Agent） |
|---|---|---|
| 法律义务对象 | 卖家 | 买家 |
| 内容天然倾向 | 讲优点，回避缺点 | 结构上更适合讲真实观察 |
| 当前市场行为 | 已经在拍视频、做营销内容 | 内容工具几乎空白 |
| 佣金证明压力（2026 新规后）| 较低（挂牌合同默认存在）| 较高（需单独协商，需证明价值）|

买方经纪是这个产品结构上摩擦最小、动机最一致的第一批用户。

# 产品原则

- 改善已有工作流，不创造新工作。
- **默认私有**。报告默认只有经纪和其指定客户可见。
- 观察先于观点：AI 输出结构化事实（房间、噪音、采光、装修状况），而不是主观评价语句。
- 人工审核后才能发送给客户——AI 生成草稿，经纪确认/编辑后才算最终报告。
- 不替经纪做判断，只帮经纪整理和呈现。

# 为什么不直接用 ChatGPT / Claude？

这是经纪常会问的问题，值得提前讲清楚：

| | 通用 AI（ChatGPT / Claude） | Kawu |
|---|---|---|
| 输入方式 | 需要自己打字描述，或上传录音后手动整理提示词 | 一键录音，自然走一圈、自然说话 |
| 结构化能力 | 通用摘要，需要自己设计房产专属的分类维度 | 内置房产专属分区（房间类型）和观察维度（噪音/采光/装修等），开箱即用 |
| 输出格式 | 纯文本，需要自己排版才能发给客户 | 直接生成品牌化、可发送的客户报告 |
| 历史管理 | 不记录、不关联客户和房源 | 自动归档到对应客户和房源，形成可搜索的工作台 |
| 使用场景嵌入 | 需要切换 App、手动操作 | 嵌入带看现场的实际工作流，边走边用 |

简单说：**通用 AI 提供的是能力，Kawu 提供的是把这个能力嵌入到带看这个具体场景里的完整工作流。**

# 核心待验证假设

| ID | 假设 | 状态 |
|----|------|------|
| H1 | 买方经纪会在每次带看时使用，如果确实省时间 | 未验证 |
| H2 | AI 生成的报告比经纪手写笔记质量更高、更愿意发给客户 | 未验证 |
| H3 | 结构化带看数据长期沉淀会形成有价值的数据资产 | 合理但未验证 |
| H4 | 部分经纪愿意在不损害自身利益的前提下，公开/半公开分享部分报告内容 | 未知，**Phase 3 才测试，不在 MVP 范围** |
| H5 | 如果 H3、H4 成立，可能演化出更大规模的买家信任内容网络 | 长期假设，不影响当前产品设计 |

# MVP 功能清单（Phase 1）

## 核心录制流程

1. **一键开始 / 结束带看**：App 首页一个按钮，开始后自动录音（可选同步录像），无需手动分段。
2. **自然语音输入**：经纪边走边说，无需按固定格式，AI 负责结构化。
3. **照片/视频拍摄**：录制期间可随时插入拍照，自动关联到当前时间点/房间。
4. **语音标记（Voice Tag）**：经纪可说出"备注：厨房 2020 年翻新"这类短句，AI 识别为独立标注点。
5. **手动结束 + 自动保存**：结束后本地/云端自动保存原始录音、照片、视频，无需手动上传。

## AI 处理流程

6. **语音转文字（Speech-to-Text）**：中英文双语支持。
7. **房间/空间识别**：AI 根据语音内容和照片自动分段到"客厅""厨房""主卧"等类别。
8. **结构化信息提取**：自动归类为——优点 / 缺点 / 买家顾虑 / 待跟进事项 / 客观观察（噪音、采光、气味、格局）。
9. **AI 生成带看总结（Draft Report）**：包含执行摘要、房间逐项记录、买家关注点、后续行动建议。
10. **草稿状态标记**：AI 生成内容默认标记为"待经纪确认"，未经确认不可发送。

## 编辑与审核

11. **报告编辑器**：经纪可直接修改 AI 生成的文字、增删条目、调整语气。
12. **转写纠错**：可对语音转文字结果做逐句修正（用于训练本地纠错，非必须联网）。
13. **敏感内容提示**：AI 检测到主观性强、可能构成诽谤/法律风险的表述（如"卖家在隐瞒问题"）时，标记建议改写为客观陈述。

## 客户交付

14. **生成客户版报告（Client Report）**：一键生成排版精美、可直接发送的报告（PDF / 可分享链接两种格式）。
15. **品牌自定义**：报告可加入经纪个人/团队 logo、联系方式，作为专业形象的一部分。
16. **多渠道发送**：支持导出到微信、邮件、短信链接分享。

## 客户与房源管理（私有工作台）

17. **私有工作台（Workspace）**：经纪的所有带看记录集中管理，按客户 / 按房源两种视角查看。
18. **客户关联**：每次带看可关联到具体买家客户，形成该客户的带看历史。
19. **多套房源对比视图**：同一客户看过的多套房源，可生成结构化对比表（优缺点并排展示），帮助买家决策。
20. **房源历史记录**：同一房源被同一经纪多次带看（不同客户），保留独立版本历史，互不覆盖。
21. **搜索与筛选**：按客户名、房源地址、日期、关键词搜索历史记录。

## 账户与基础设施

22. **经纪个人账户**：邮箱/手机号注册，基础资料设置。
23. **移动端 App**：iOS + Android，作为主要入口（带看现场必须用手机操作）。
24. **数据本地优先 + 云端同步**：录音/照片本地缓存，网络恢复后自动同步，避免带看现场信号不好导致数据丢失。
25. **基础订阅付费**：月付订阅制，按报告生成数量或使用量分层定价（具体定价待验证阶段确定）。

# 明确不包含在 MVP 中

以下功能在 Phase 1 **刻意排除**，原因逐项说明：

| 功能 | 排除原因 |
|------|---------|
| 公开分享 / Marketplace | H4 未验证，公开分享涉及的隐私、法律、经纪同行关系风险尚未评估 |
| GPS 信任评分 / Proof of Visit | 私有工具不需要"验证经纪是否真的到场"，这是公开网络场景才需要的机制 |
| 维修成本估算 | 责任风险高，AI 估算若被客户当作决策依据，出错可能牵连经纪 |
| 收入分成 / Passive Income | 依赖 H4、H5 成立，现阶段无意义 |
| 跨经纪内容聚合 | 属于 Network 假设范畴，与当前私有工具定位冲突 |
| 完整 CRM 集成 | Phase 2 功能，MVP 阶段只需最基础的客户关联，不需要打通外部 CRM |
| 团队协作 / 多经纪共享工作台 | Phase 2 功能 |

# 数据模型（简化版）

```
Agent (经纪)
  └── Client (买家客户)
        └── Visit (单次带看)
              ├── Property (房源信息)
              ├── Raw Media (录音/照片/视频)
              ├── Transcript (转写文本)
              ├── Structured Report (AI 生成 + 经纪编辑后的报告)
              └── Status (草稿 / 已确认 / 已发送客户)
```

Property 可能被多个 Visit 引用（同一房源、不同客户、不同时间），每个 Visit 是独立版本，不互相覆盖。

# 验证计划

**招募对象**：3-5 位活跃买方经纪（优先选择不同时做挂牌业务的纯买方经纪），可从现有华人经纪社区资源切入。

**测试周期**：2 周免费试用。

**North Star Metric：Client Reports Delivered（实际发送给客户的报告数）**

不用"录制次数"作为北极星指标——录制只代表使用了工具，发送给客户才代表经纪信任这份输出、愿意用自己的专业声誉为它背书。这是比使用量更真实的信任信号。

**核心测量指标**：

- 每周带看记录次数 / 实际带看总次数（目标 ≥80%）
- **Client Reports Delivered**：生成的报告中，实际发送给客户的比例（核心指标）
- 试用结束后，主动要求继续使用的人数（目标 ≥3 人）
- 真实付费意愿（试用到期后是否愿意付费续用，而非访谈中的假设性回答）

**额外验证问题（为 Phase 3 铺垫，不影响 MVP 设计）**：

- 2026 新佣金规则下，是否感受到更大压力要向客户证明自身价值？
- 是否愿意将某次报告中的"买家视角"部分，半公开分享（如发朋友圈），而非发给陌生大众？

# Roadmap

## Phase 1（当前）— Showing Intelligence
私有 AI 带看记录工具。目标：验证 H1、H2，跑通日常工作流采用率。

## Phase 2 — Realtor Collaboration
团队协作、CRM 集成、客户端 Portal（买家可登录查看经纪主动分享给自己的报告，仍是权限控制下的私有分享，不对陌生人公开）。

## Phase 3 — 小范围分享实验
挑选愿意的经纪，测试"半公开分享单份报告"这一行为是否真实发生（验证 H4）。这是一个受控实验，不是产品功能全量上线。

## Phase 4 — Buyer Intelligence Network（假设阶段）
只有在 Phase 3 得到真实数据支持之后，才评估是否值得投入。**这不是既定路线图，是一个条件分支。**

# 长期方向的诚实表述

如果 H3、H4 被验证为真，Kawu 有可能演化为更大的买家决策信息网络——但这是**一个有待未来数据支持的可能性，不是今天产品的组成部分**，也不应该出现在今天面向用户的产品叙事里。今天的用户故事只有一句：

**"帮买方经纪更高效地为客户做好带看记录，赢得客户信任。"**

# 风险

1. 经纪抵触改变现有工作习惯。
2. AI 报告质量不足以让经纪愿意发给客户（信任门槛）。
3. 隐私顾虑：在他人住宅内录音录像涉及的同意问题，需明确产品内的授权/免责流程。
4. 现有房产科技厂商可能快速跟进类似功能。
5. 商业模式尚未验证：订阅定价、经纪付费意愿仍是假设。

每项风险都通过验证阶段的真实用户数据来决定是否值得继续投入，而不是提前假设已解决。

# 技术架构说明

底层数据模型和 AI Pipeline 采用行业中立的设计（通用核心 + 地产配置层），便于未来若验证出扩展需求时降低重建成本。**这只是工程层面的预留，不改变本文档定义的产品范围、目标用户和当前阶段的功能边界。** 详见配套文档《Kawu Technical Architecture》。
